EQL existential semantics: binding order, semi-join exists, and range restriction

0 / 10 done

Rebuild EQL's existential operator on the standard relational/logic-programming footing. Today exists() takes a redundant quantified variable, exports bindings from inside the quantifier, and short-circuits globally rather than per outer binding — which silently drops matching rows, breaks not_(exists(...)) and for_all(...), and turns a correlated existential into a cross product. The root cause is that bottom-up evaluation gives the quantifier no outer relation to filter, so the operator invented one. The plan fixes the evaluation model first, then makes exists a semi-join and negated exists an antijoin, then removes the now-dead first argument and updates its two consumers — measuring evaluation cost before and after throughout.

EQL match query ergonomics: drop the .expression / .variable detours

2 / 7 done

Remove the two documented detours match queries force on users - match.expression for symbolic attribute access and quantification, and match.variable for where-conditions. Root cause: Match does not follow the CanBehaveLikeAVariable underscore-sandwich convention Query uses, so its plain public fields (parent, variable, type, conditions, domain, factory, kwargs, ...) shadow domain attribute names and symbolic access cannot be forwarded. The two handles also silently diverge: a where-condition built from a query-rooted attribute does not filter at all, and a selection built from match.variable drops the match's conditions. Fix the semantics bug first, then make Match behave like a variable, then let the factories accept a Match directly and migrate consumers and docs.
